Register Allocation
• What have we learned so far?
• The source program is translated into machine IR.
• A sequential intermediate representation.
• Types and operations are aligned to the target machine.
• The only problem is that machine IR uses virtual registers.

--- PAGE 3 ---
Register Allocation
• Problem statement
• Given an intermediate representation that uses a set of
virtual registers, find a map from virtual registers to
physical registers.
• Spilling
• As the number of virtual registers is not limited, it may fail
to map all virtual registers to physical registers.
• Some virtual registers have to be “spilled” to the stack.
• Requirements
• Produce correct codes when the virtual registers are
replaced with physical registers.
• Minimize the overhead of introduced loads and stores.
• Minimize the number of spilled registers.

--- PAGE 4 ---
Register Allocation via Graph Coloring
• Graph coloring
• Assign labels (colors) to vertices such that no two adjacent vertices have the same
color.

--- PAGE 5 ---
Register Allocation via Graph Coloring
• Idea
• Many allocation problems are hard to solve.
• Register allocation is NP‐complete.
• We convert register allocation problems into graph coloring problems.
• Vertices are used to represent virtual registers.
• Each color is considered as a physical registers.
• Two adjacent vertices do not share the same color (physical register).
• Issue
• Graph coloring is also NP‐complete.
• A heuristic algorithm is proposed to solve graph coloring problems.
• Chaitin’s algorithm.

--- PAGE 6 ---
Register Allocation via Graph Coloring
• Sketch of algorithm
• Perform liveness analysis.
• Construct interference graph 𝐺 using the result of liveness analysis.
• Assign 𝑘 colors to 𝑛 vertices of the graph.
• Heuristic:
• 𝐺 is 𝑘‐colorable iff 𝐺 – {𝑣} is 𝑘‐colorable, where 𝑣 is a vertex with 𝑘 – 1 edges.
• Select a vertex 𝑣 with fewer then 𝑘 edges.
• Recursively color 𝐺 (cid:3398) (cid:4668)𝑣(cid:4669).
• Assign a valid color to 𝑣 in 𝐺.

--- PAGE 45 ---
Register Allocation via Graph Coloring
• Algorithm
• 1. Build the interference graph 𝐺 via liveness analysis.
• 2. Try to color the interference graph.
• 3. The algorithm terminates if G is k‐colorable.
• 4. Spill a vertex whose number of edges is larger than 𝑘.
• The selection of a vertex to spill is also heuristic.
• 5. Rewrite the program by adding loads and stores.
• 6. Goto 1.

--- PAGE 46 ---
Register Allocation via Graph Coloring
• Other potential improvements
• Coalescing
• Some optimizations may increase live ranges that cause register pressure.
• For example, copy propagation and common subexpression elimination.
• It can be avoid by merging vertices in the interference graph.
• Given a statement a = b, we can coalesce a and b in the graph if a and b do not interfere
each other.
• When a and b are assigned the same register ti, the original statement can be rewritten as
ti = ti.
• This redundant statement will be removed by other optimizations.
• Risks
• Coalescing may make a 𝑘‐colorable graph uncolorable.

--- PAGE 47 ---
Linear Scan
• Idea
• A greedy algorithm proposed by Poletto & Sarkar.
• https://dl.acm.org/doi/abs/10.1145/330249.330250
• Use live interval to express the liveness of variable.
• Scan the linear IR from the first statement to the last statement.
• When a live interval begins at the current scan point, give a free register to the
variable.
• When a live interval ends at the current scan point, free the register assigned to
the variable.
• However, spilling variables is still inevitable.

--- PAGE 48 ---
Linear Scan
• Live intervals
• The live range of a variable is the set of program locations where the variable is
live.
• Given a sequential IR of program, the live interval of a variable is the smallest
subrange of IR containing all alive ranges.
• Live intervals are less precise compared to live ranges.
• It is more suitable for register allocation.
